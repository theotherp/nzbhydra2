## Outcome

On a phone (owner screenshot at 390px, 2026-09-03) the desktop toolbar wraps into seven rows and "Refine" scrolls away below the
sticky region. Below the 768px stacking breakpoint the toolbar becomes one sticky row, a second sticky row appears only while something
is selected, paging moves to a footer under the last card, and Refine opens the shared refine surface as a bottom sheet — one
region's layout plus one shared shell, shipped together; desktop is untouched.

## Decision Dependencies

ADR-0046 (one refine-surface concept: the shell's compact branch changes for every consumer, history views included);
ADR-0011 (cards below 768px, no horizontal scroll); ADR-0014; ADR-0054 (no new persisted key).

## Acceptance

- **Branching**: every phone/desktop difference is decided in JavaScript by `useCompactRefineSurface()` (below 768px), never by
  CSS `display`, so each `data-testid`/accessible name exists exactly once at any width — including select-all at 600–767px.
  `results-toolbar` stays the sticky element (`top: 0`); phone padding `8px 0`, `gap` 8px; ≤ 56px tall idle at 390x844.
- **Row 1**, in order: `toolbar-selection-menu` (labels unchanged); `search-results-summary` reading `{filtered} / {total}`
  (`720 / 720`; `28 / 28 · ` + `results-rejected-trigger` when rejected > 0; no loaded/available/filtered/selected fragments);
  right-aligned `IconButton`s: `display-options-toggle` (`TuneIcon`, `aria-label="Display options"`, same popover and entries);
  `refine-sidebar-toggle` (`FilterListIcon`, existing expand/collapse labels, `aria-expanded`, `aria-haspopup="dialog"`) in a MUI
  `Badge` showing `activeFilterCount` (hidden at 0); `save-search` (`BookmarkAddOutlinedIcon`, `aria-label="Save search"`,
  `aria-busy` while saving — reachable without a selection, which row 2's overflow could not give it). No paging buttons.
- **`activeFilterCount`** (pure, `resultTable.ts`, unit-tested): the `ResultFilters` dimensions — title, categories, indexers,
  downloadTypes, size, age, grabs, quickFilters — differing from `defaultFilters(results, quickFilters)`; 0 exactly when
  `refine-clear-all` is disabled (`hasActiveFilters` adopts the same comparison).
- **Row 2** (`results-bulk-actions`) only while `selected.size > 0`; bar with it ≤ 104px tall: `results-selection-count`
  (`{n} selected`); `send-to-downloader` (`variant="contained"`, `primaryActionSx`, text `Send to downloader`, same disabled
  rules) joined to `send-to-downloader-options` (`aria-label="Send options"`, `aria-haspopup="menu"`) opening
  `send-to-downloader-menu`: `Downloader` subheader + one `menuitemradio` per downloader (only when `downloaders.length > 1`),
  `Category` subheader + the desktop category `Select`'s options as `menuitemradio`; `aria-checked` on the current choice; the same
  `selectedName`/`category` state the desktop `Select`s bind, in one component. `results-more-actions` (`MoreVertIcon`, `aria-label=
  "More actions"`) opens `results-more-actions-menu`: `Download selected NZBs as ZIP`, `Send selected to black hole`, `Copy
  selected links`, each under its desktop gating and disabled rule.
- **Paging footer** `results-paging-footer` (phone branch, after the table, whenever `onLoadMore` is set — also with zero loaded
  results): `results-load-more` and `results-load-all` (labels, `disabled`/`aria-busy` unchanged), `flex: 1` each, `gap` 8px,
  `padding: 16px 0`, preceded by `{availableResultsPhrase} available` (`>500 available`) while more exist.
- **Bottom sheet** (`RefineSurface` compact branch, every consumer): `SwipeableDrawer anchor="bottom"`, `disableSwipeToOpen`,
  paper `maxHeight: 85vh`, top corners 12px (the `MuiPaper` raised radius, justified at the site), body scrolls inside, header =
  summary + close (`testIds.close`); a footer pinned at the bottom with `testIds.clearAll` as a text button `Clear all`
  (`variant="control"`, `startIcon` `ClearAllIcon`, accessible name still `Clear all filters`) and a `variant="contained"`
  `labels.done` button (`testIds.done`; results: `refine-sidebar-done`, `Show N results` / `Show 1 result` from the filtered
  count; history: `Done`) closing the sheet. Filters apply live, as the docked column and today's drawer do — no draft state.
  New prop `trigger?: "inline" | "external"` (default `inline`): the results page passes `external` and renders row 1's trigger.
- **Desktop unchanged**: `refine-sidebar` outerHTML at 1280x800 identical before/after (FM-136's method); the desktop toolbar
  and summary phrase unchanged; `search.spec.ts:88` and `focus-indication.spec.ts` still pass.
- Tests: component tests for row 1/row 2 gating, `activeFilterCount`, the sheet footer, the 600–767px select-all; the four
  rewritten `results.spec.ts` mobile branches plus a new case pinning both bar heights and the footer below the last card at
  390x844; history mobile drawer cases re-run against the sheet. No page-level horizontal overflow (`html.scrollWidth`). Strip
  per `../README.md` *Visual Gate*, 390x844: bar idle; bar with row 2; `send-to-downloader-menu` open; sheet open with a badge
  ≥ 1; footer with the last card in frame; plus 1280x800 results proving desktop unchanged (`fm181-before-` copies taken first).
