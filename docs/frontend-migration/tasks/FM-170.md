# FM-170: Copy A History Value Without Selecting It By Hand

Status: planned Owner:
Feature IDs: F-HISTORY-SEARCHES, F-HISTORY-DOWNLOADS, F-HISTORY-NOTIFICATIONS
Component IDs: C-COPY-VALUE-BUTTON (reserved, planned)
API IDs: None
Depends on: None
Blocks: None

## Outcome

The values people actually take out of history — a query to re-run elsewhere, a notification body or URL, a release
title, the IP or user agent behind a search — become one click to copy instead of a careful drag across a table cell.
The app has exactly one clipboard affordance today, `DownloadActions.tsx:265-292` with its "Copy selected links" button
at `:439-441`, and no history page has any. One small shared button serves all three pages plus the search details
dialog; three bespoke copy handlers would cost the same review for less. It depends on FM-166 only for sequencing —
that packet is already editing all three pages.

## Acceptance

- A copy affordance appears on exactly these values, chosen by one stated rule — free text or machine-generated
  identifiers a user pastes elsewhere, which no existing action already yields: search history's Query, Additional
  parameters, User agent, and IP address; the details dialog's Host and User agent; download history's Title and IP
  address; notification history's Title, Body, and URLs. Time, Category, Source, Result, Age, Indexer, Type, and
  Username get none. The rule is written into the `COMPONENTS.yaml` record so the next adopter is not guessing.
- The affordance is one `CopyValueButton`: an icon button always present in the DOM, visually revealed on row hover and
  whenever it has focus, so it is reachable by keyboard alone and never hides a tab stop behind a hover state. Each
  instance carries an `aria-label` naming its value ("Copy query", "Copy notification body", …) and a per-column
  testid; the icon is stock MUI and the styling comes from the theme (ADR-0014 / *UI Conventions*).
- Copying confirms through `C-TOAST-SERVICE` with a short message, and a failed write toasts a failure the way
  `DownloadActions` already does. The copied text is the cell's underlying value, not its rendered or truncated form —
  pinned by a test on a value the cell visibly truncates.
- Where `navigator.clipboard` is unavailable no button renders at all, rather than a control that always fails; a test
  pins both branches.
- The three page suites gain a case each proving the button copies the right value, every existing assertion stays
  green, and row, cell, and column testids are unchanged.
- `C-COPY-VALUE-BUTTON`'s reserved `COMPONENTS.yaml` record moves from `planned` to `done`, its selection rule checked
  against what shipped. The three `F-HISTORY-*` records list the new selectors and record the affordance as a
  capability legacy did not have.
- Screenshot strip per `../README.md` *Visual Gate*: a history row at rest, hovered, with the button keyboard-focused,
  and the confirmation toast at 1280x800, plus 390x844 showing the buttons do not push any table past its scroll floor.
