# FM-163: Lazy-Load The Chart And Non-Search Routes Out Of The Entry Bundle

Status: planned Owner:
Feature IDs: F-STATS-MAIN, F-PLATFORM-LIVE-STATUS
Component IDs: C-DOWNLOADER-STATUS
API IDs: None
Depends on: None
Blocks: None

## Outcome

A visitor who only searches stops downloading the stats, system, and config code — and the chart engine underneath it —
before the search page can paint. `vite.config.ts` declares no `manualChunks`, nothing in `src/` uses `lazy` or
`Suspense`, and the build emits one JS file: `dist/assets/index.js`, 1,747,122 bytes. The load-bearing detail is that
lazying the stats route alone would not help: `@mui/x-charts` is imported from `charts/HorizontalBarChart.tsx:3` and
`charts/GroupedBarChart.tsx`, from `features/system/bugreport/CpuUsageCard.tsx:18`, and from
`app/status/DownloaderStatusFooter.tsx:7`, which `AppShell.tsx:30` mounts on **every** route — so all three sites must
become dynamic or the payload stays in the entry chunk. `vite.config.ts:20-28` already anticipates split chunks and
`scripts/validate-production-assets.mjs:33-41` already exempts hashed ones, so ADR-0010 needs no change.

## Decision Dependencies

- ADR-0010 (React production CSS delivery) — binding: `assets/index.js` and `assets/index.css` stay the only unhashed,

## Acceptance

- The stats, system, and config route subtrees load through `React.lazy` behind a `Suspense` boundary; the search route
  and the app shell stay eager. Each lazy route renders its real content once resolved, and the fallback is a
  non-jumping placeholder in the content area, not a full-page spinner over the shell.
- `DownloaderStatusFooter` still renders state, queue, and title eagerly; only the `SparkLineChart` is deferred into its
  own module behind `Suspense`, with reserved space so the footer's height does not change when it arrives.
- `npm run build` emits `dist/assets/index.js` plus at least one hashed JS chunk, and the entry is at most 1,250,000
  bytes (from 1,747,122). The handoff records exact before/after sizes and the emitted chunk list.
- The entry chunk contains no `@mui/x-charts` or `d3-*` code, and `validate-production-assets.mjs` gains a check that
  fails when it does — demonstrated red against the current single-chunk output and green after.
- `validate:production-assets` and `validate:migration` still pass with `react.html` untouched: its two pinned names
  resolve, every other emitted chunk is hashed, and no `modulepreload` requirement is introduced.
- `smoke.spec.ts` still proves the cookie-less entry load and the `/system/tasks` deep link rendering its real body —
  that link now crosses a lazy boundary, making it the packet's real-server proof. Waits may be added; no assertion is
  removed. `AppShell.test.tsx` and `DownloaderStatusFooter.test.tsx` stay green, resolving the deferred sparkline with
  `findBy*` rather than dropping the assertion.
- Screenshot strip per `../README.md` *Visual Gate*: the stats route's fallback and its resolved state at 1280x800, and
  the footer with and without the sparkline at 1280x800 and 390x844 (proving the reserved space).
