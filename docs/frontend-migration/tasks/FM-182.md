# FM-182: Sort Menu For The Phone Card Layout

Status: planned Owner:
Feature IDs: F-SEARCH-SORT-FILTER
Component IDs: C-RESULT-TABLE
API IDs: None
Depends on: FM-181
Blocks: None

## Outcome

Below the 768px stacking breakpoint the table's `thead` is hidden, and with it the only sort control, so a phone user cannot
sort results (owner report 2026-09-03). FM-181's sticky bar gains a Sort icon button between the count and Display that opens
a menu of the six sortable columns with the active one checked and a direction choice. It writes the same `sorting` state the
desktop headers write, so the choice persists through `hydra.search-results.table` and a viewport change never disagrees
with the header arrows. One control, its menu, its tests and its registry line — a single capability.

## Decision Dependencies

ADR-0054 (sorting stays in `localStorage` under the existing key; no new key); ADR-0014.

## Acceptance

- `results-sort-toggle`: an `IconButton` (`SwapVertIcon`, `aria-label="Sort results"`, `aria-haspopup="menu"`,
  `aria-expanded`) rendered in FM-181's row 1 between `search-results-summary` and `display-options-toggle`, on the phone
  branch only (decided by `useCompactRefineSurface()`, absent from the DOM at ≥ 768px). FM-181's idle-bar height bound
  (≤ 56px at 390x844) still holds with it present; no page-level horizontal overflow.
- `results-sort-menu`: a MUI `Menu` whose first group is six `menuitemradio` items in table order — `Title`, `Indexer`,
  `Category`, `Size`, `Details`, `Age` — `aria-checked="true"` on the column of `sorting[0]` (none when `sorting` is empty);
  then a `Divider`; then two `menuitemradio` items `Ascending` / `Descending`, checked from `sorting[0].desc`, both
  `disabled` while `sorting` is empty. Menu rows use `SelectionMenu.tsx`'s density.
- Picking a column sets `sorting` to `[{id, desc}]` where `desc` is the current sort's direction when one is active, else
  `column.getAutoSortDir() === "desc"`; picking a direction keeps the column and sets `desc`; every pick closes the menu.
  Both go through the existing `setSorting`, so the rows re-order, the persist effect writes `sorting`, and after resizing to
  1280px the matching header carries `aria-sort` for the same column and direction (asserted in the browser).
- Tests: component tests for the checked states, both pick rules, the empty-`sorting` case and absence at desktop; one new
  `results.spec.ts` case at 390x844 sorting by Size descending then Title ascending, checking the first card's title after
  each and the desktop header's `aria-sort` after `setViewportSize(visualViewports.desktop)`.
- Strip per `../README.md` *Visual Gate*, 390x844: bar idle with the Sort button; `results-sort-menu` open; the cards after a
  Size sort; plus 1280x800 results proving no Sort button and unchanged headers.
