# FM-193: The Settings Index Becomes The Source Of Labels And Help

Status: ready Owner:
Feature IDs: F-CONFIG-SHELL, F-CONFIG-MAIN, F-CONFIG-AUTH, F-CONFIG-SEARCHING, F-CONFIG-CATEGORIES, F-CONFIG-DOWNLOADING, F-CONFIG-EXTERNAL-TOOLS, F-CONFIG-INDEXERS, F-CONFIG-NOTIFICATIONS

## Outcome

`settingsIndex.ts` (1059 lines, 146 entries) hand-copies the `label` and help of every indexed setting out of the tab JSX,
which its own doc comment (`:4-21`) records as unavoidable "because the tabs define their fields as JSX, not as data".
The copies can silently disagree: `settingsIndexDrift.test.tsx` compares `config-setting-*` ids only, so a wrong label or
stale help string in the index is caught by nothing, and `CSRF_HELP` (`main/mainSettings.ts:110`) exists as a one-off
shared constant precisely to stop that drift for a single string. This task inverts the dependency: the index declares
label and help once and the tabs read from it, so search, the review-changes panel and the feedback banner quote what the
user sees by construction. Behaviour-preserving — identical labels, help, links, order, search results. Backlog item 29.

## Decision Dependencies

ADR-0002 (a typed field vocabulary, not a schema framework — the tabs stay JSX), ADR-0024 (tooltips stay separate from
help), ADR-0039 (search hides matches whose render condition is unmet), ADR-0014.

## Acceptance

- Each index entry carries the structured `HelpContent` the control renders — links intact, not flattened — with the flat
  search string derived from it, so `settingsSearchMatching.ts` matches the text it matches today. Where an entry's
  `helpText` is not the flattening of the rendered help, the rendered help wins and the difference is reported.
- Each indexed control takes its `label` and `help` from the index by config path through one lookup helper, not from a
  literal in the tab JSX. No indexed label or help string is declared twice at the end of this task.
- `settingsIndexDrift.test.tsx` gains a fourth direction: for every non-conditional entry the rendered row's label and
  help text equal the index's, asserted from the DOM — the check that would have caught a wrong string before.
- Rendered output is proven unchanged, not argued: render all eight tabs at base and after, advanced toggle on and off,
  and dump each tab's `outerHTML` plus the emotion stylesheet; every pair is byte-identical including class hashes
  (FM-136's method). Additionally dump `SETTINGS_INDEX` as ordered JSON — path, label, flattened help, tab, fieldset,
  `advanced`, `conditional`, `anchorTestId`, `kind` — at base and after; the only permitted differences are the corrected
  drift entries, each named and justified.
- Every existing case in `settingsIndex.test.ts`, `settingsIndexDrift.test.tsx` and the eight tab suites keeps its
  assertions; edits are limited to imports and helper names. All `config-setting-*`, `config-input-*`,
  `config-fieldset-*`, `config-nav-anchor-*` and `config-repeat-*` ids are unchanged. No screenshot strip.
