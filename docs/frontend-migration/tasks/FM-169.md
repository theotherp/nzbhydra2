# FM-169: Give The Stats Tables The Narrow-Viewport Scroll Treatment

Status: planned Owner:
Feature IDs: F-STATS-MAIN, F-STATS-INDEXERS
Component IDs: C-TABLE-SCROLL-AFFORDANCE
API IDs: None
Depends on: None
Blocks: None

## Outcome

Every stats table gets the treatment ADR-0038 already sanctioned for history and config: a measured `minWidth` floor so
columns stop wrapping mid-word at 390px, container scrolling, and a visible cue that more table exists to the right.
Seven `TableContainer`s render bare today — `IndexersSection.tsx:114,435,466`, `ActivitySection.tsx:137`,
`SourcesSection.tsx:153`, `DownloadAgeSection.tsx:78`, `IndexerStatusesPage.tsx:87` — while `SearchHistoryPage.tsx:
266-282` shows the finished pattern. This was refused as a quickfix on 2026-08-31 (`MAINTENANCE.md`, *Open candidates*)
for the right reason: it needs new scroller testids, new consumers on a registry record, and floors measured against a
real 390x844 render. It depends on FM-164 only for sequencing — both edit the same four section components.

## Decision Dependencies

- ADR-0038 (narrow-viewport tables: container scroll plus a scroll-edge affordance) — binding, with its constraints
  intact: no column dropping or merging below `sm`, one shared mechanism, fresh 390x844 strips per route. This packet
  applies the decided pattern to more tables; it does not revisit the decision.
- ADR-0021 (charts secondary, tables the accessibility layer) — binding: these tables are the accessible rendering of
  the charts beside them and must stay readable at 390px.

## Acceptance

- Each of the seven containers either renders through `TableScrollAffordance` with a unique, descriptive
  `scrollerTestId` and a `minWidth` floor, or is recorded in the handoff as measured and found not to need one.
- Every floor is measured, not guessed: the implementer renders each table at 390x844 with realistic data, finds the
  width below which its columns wrap mid-word, and records that value with a short justifying comment beside it, in the
  shape `SearchHistoryPage.tsx:270-281` uses. The handoff lists each table and its chosen floor.
- At 390x844 no stats table wraps a heading or value mid-word, each over-wide table scrolls inside its own container
  rather than pushing the page sideways, and the edge cue stays visible until the container is scrolled to its end.
- At 1280x800 nothing changes: the floors sit below the available width and the tables render exactly as today.
- `C-TABLE-SCROLL-AFFORDANCE` gains `F-STATS-MAIN` and `F-STATS-INDEXERS` as consumers and the two feature records list
  the new scroller selectors; the component record's `state` and responsibility text are untouched.
- `IndexerStatusesPage.test.tsx` renders under `createHydraTheme` (it does not today), discharging that part of the
  standing follow-up candidate for a suite this packet already edits.
- `stats.spec.ts` gains one 390x844 case per route touched (dashboard, indexer statuses) proving the scroller exists
  and the page does not scroll sideways, modelled on the history affordance specs; chart and value assertions are
  unchanged.
- Screenshot strip per `../README.md` *Visual Gate*: every affected table at 390x844 (unscrolled with the cue, and
  scrolled to the end with it cleared) plus one 1280x800 capture per route proving no change.
