# FM-189: Persist The Two Grouping Display Options Across Searches

Status: planned Owner:
Feature IDs: F-SEARCH-SORT-FILTER, F-SEARCH-GROUP-SELECTION
Component IDs: C-RESULT-TABLE
API IDs: None
Depends on: None
Blocks: None

## Outcome

The owner reports (2026-09-08) that "Group TV episodes" comes back checked after every new search, so same-episode results
are always collapsed whatever was unchecked. Cause: `groupEpisodes` and `groupTorrentAndUsenet` are bare `useState` in
`SearchResults.tsx` (:544-545), absent from the persisted `hydra.search-results.table` payload, and `SearchPage.tsx` drops
`state.data` on every submit (`setState({loading: true})`, :280), remounting `SearchResults` onto those defaults. Both
join the payload the way `showCovers` did, with legacy's defaults (`search-results-controller.js` at `3ce28441e^`:
`groupEpisodes` true, `groupTorrentAndNewznabResults` false), so a first load is unchanged and later searches keep the choice.

## Decision Dependencies

ADR-0054 (results display options persist in browser `localStorage` under `hydra.search-results.table`, not server-side).

## Acceptance

- `StoredChoices` gains optional `groupEpisodes?: boolean` and `groupTorrentAndUsenet?: boolean` (the React state names,
  each with a short comment naming the legacy key and default). Both states initialize as `choices.groupEpisodes ?? true`
  and `choices.groupTorrentAndUsenet ?? false` — nullish coalescing, so a stored `false` is honoured — and the persist
  effect writes both keys and lists both in its dependency array. Grouping honours the restored value on the first render.
- A payload without the keys (any earlier build) and unavailable/blocked storage both yield the defaults without throwing;
  the popover defaults list (:3389-3390) and the system entry-list (:2054-2055) stay exactly as they are.
- Unit round-trip, extending the :3931 case (not a replacement): after unchecking "Group TV episodes" and checking "Group
  torrent and Usenet results", the stored payload matches `{groupEpisodes: false, groupTorrentAndUsenet: true}`, the
  sorted key set becomes `compactRows, groupEpisodes, groupTorrentAndUsenet, highlightRecent, refineCategoryOpen,
  refineIndexerOpen, showCovers, showDuplicateControls, sidebarCollapsed, sorting`, and a remount over the same storage
  shows both options in their flipped state. One further case seeds `{groupTorrentAndUsenet: true}` before mount and
  proves `duplicateAcrossDownloadTypes` renders one grouped row from the first render (behaviour, not just the checkbox).
- A seeded `{groupEpisodes: false}` suppresses the group-episodes help dialog on an otherwise eligible search (legacy
  parity: `$scope.foo.groupEpisodes` fed `isGroupEpisodes`); pinned in the help-dialog block, no case deleted. The :2565
  comment no longer claims `useState(true)`. No assertion is loosened.
- System evidence in `results.spec.ts`: one case searches, unchecks "Group TV episodes", checks "Group torrent and Usenet
  results", runs a second search (the owner's exact path — no reload needed for the defect), and asserts both checkboxes
  keep their state and the payload contains `"groupEpisodes":false`; then re-seeds the payload via `addInitScript` per the
  FM-089 case, reloads, searches, and asserts the same two states.
- `F-SEARCH-SORT-FILTER`: the persisted-key comment gains `groupEpisodes` and `groupTorrentAndUsenet` with a
  `2026-09-08 (FM-189)` note that they default to legacy's true/false; no gap line (this restores parity, it records none).
- No rendering change; the handoff records `None (no rendering change)` for the Visual Gate.
