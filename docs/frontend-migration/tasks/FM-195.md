## Outcome

Custom mappings leave the advanced fieldset at the foot of Searching for their own configuration tab at
`/config/customMappings`, where a mapping can be named, switched off and reordered, and is kept together with the example
inputs it was written for: the example field becomes multi-line and is saved with the mapping, and testing runs every line
through FM-194's batch endpoint, showing per line what this mapping and what the whole chain do. The React half of issue
#902, at the owner's 2026-09-13 request to split it by layer against `tasks/README.md`'s "never split by layer" rule.

None. ADR-0014 (stock MUI anatomy, tokens from `theme.ts`), ADR-0003 and ADR-0039 constrain the work; owner decisions are in
Acceptance.

## Acceptance

- `CONFIG_TABS` gains `{path: "customMappings", label: "Custom Mappings"}` directly after `searching` (nine tabs; the
  eight-tab comment corrected), `ConfigNav` carries an icon, `routes.tsx` mounts a lazy `CustomMappingsConfigTab`, and a
  registration/route case proves `/config/customMappings` renders the section rather than `ConfigTabPlaceholder`.
- The section and dialog move to `features/config/customMappings/` and `SearchingConfigTab` loses the fieldset. The tab
  renders the section directly, **not** behind an advanced expander — FM-131 gated it only because it sat at the foot of
  Searching, and a tab hidden entirely while the advanced toggle is off cannot be reached. The settings-index entry moves to
  tab `customMappings`, drops `advanced` and `fieldset`, and keeps its `config-repeat-searching-customMappings` anchor.
- Dialog at `maxWidth="md"`: an optional `Name` field at the top (`config-custom-mapping-name`), an `Enabled` switch beside
  "Match whole string" (`config-custom-mapping-enabled`), and the example field as a `multiline` `TextField` with
  `minRows={3}` bound to `draft.examples` (split on newlines, blank lines dropped on submit) and saved with the mapping —
  retiring `config-custom-mapping-exampleInput` for `config-custom-mapping-examples`, the one testid this packet replaces.
- Testing runs every line into a table (`config-custom-mapping-results`), a row per example
  (`config-custom-mapping-result-<line index>`) holding input, this mapping's output or "No match", the chain's output, and
  which mappings applied, by name where set and by index otherwise, errors keeping the current red treatment. The section
  passes the full list plus the edited index, so the chain reflects unsaved edits to other entries.
- Section: an entry's legend is its `name` when set, else "Mapping N"; a disabled entry carries a `Chip` labelled "Disabled"
  (`config-custom-mapping-disabled-<index>`); each entry gains `ArrowUpward`/`ArrowDownward` `IconButton`s
  (`config-repeat-up-searching-customMappings-<index>` and `-down-`, disabled at first and last) writing the reordered array
  through `setValue(..., {shouldDirty: true})` and invalidating the open transaction as `remove` does. Help text under the
  list: "Mappings run top to bottom. A whole-string mapping that matches stops the list."
- `CustomMappingValues` gains `name`, `enabled` (true when absent) and `examples`; the client sends FM-194's batch request
  and refuses more than 200 lines with a message instead of provoking the 400.
- Tests: dialog cases for multi-line examples surviving submit into the committed entry and for the result table's match,
  no-match and error rows; section cases for move up and move down including transaction invalidation, the disabled chip and
  the name legend; a `customMappings` case in `settingsIndexDrift.test.tsx`; and a `reviewChangesDiff.test.ts` case proving
  a mapping row's origin reads "Custom Mappings".
- Screenshot strip per `../README.md` *Visual Gate*: the tab with one enabled and one disabled mapping, the dialog with
  several example lines, and the result table after a test, at 1280x800 and 390x844.
