# FM-166: One Shared History Pager With Page Jumps And A Page-Size Choice

Status: planned Owner:
Feature IDs: F-HISTORY-SEARCHES, F-HISTORY-DOWNLOADS, F-HISTORY-NOTIFICATIONS
Component IDs: C-HISTORY-PAGER (reserved, planned)
API IDs: None
Depends on: FM-165
Blocks: FM-170

## Outcome

The three history pages get back the navigation legacy had and gain the page size it never offered. Each page hand-rolls
the same two-button strip — `SearchHistoryPage.tsx:418-434`, `DownloadHistoryPage.tsx:324-340`,
`NotificationHistoryPage.tsx:272-289` — offering only Previous/Next and "Page N of M"; only notifications shows a total;
and `shared/pageSize.ts:7` fixes every page at 25 rows with a comment recording that no control exists. Legacy's
`dirPagination.tpl.html` had boundary (first/last), direction, **and** numbered page links, and all three legacy
controllers requested `limit = 100` (`download-history-controller.js:7` and its two siblings), so 25 rows with no way to
jump is a double regression. One shared component fixes all three at once. It depends on FM-165 because the chosen page
size belongs in that packet's URL schema rather than in a second state channel.

## Acceptance

- One `HistoryPager` renders on all three pages with first, previous, a bounded run of numbered page buttons with an
  ellipsis for the gap, next, and last; edge buttons disabled at the edges; the current page marked
  `aria-current="page"`. A single-page result keeps the status text with controls disabled rather than removed.
- All three pages show the same status text including the total — "Page N of M · X <entries>", noun singular/plural per
  page — replacing the two that showed none. Each status carries a testid, and `notification-history-page-status` keeps
  its exact id and text shape so its existing spec assertion holds.
- A page-size control offers 25, 50, and 100 with a visible label (ADR-0014 / *UI Conventions*), defaults to today's 25,
  and writes through FM-165's URL schema, so a chosen size survives reload, Back, and sharing. Changing it resets to
  page 1 and refetches with the new `limit`; the payload is otherwise unchanged.
- `PAGE_SIZE` becomes the default of an exported option list rather than a hard-coded constant, its file comment is
  rewritten to what is now true, and `pageSize.test.ts` pins both the default and the options.
- Legacy's fixed `limit = 100` and the absence of a legacy page-size control are recorded as gap lines on the three
  `F-HISTORY-*` records, so a reader can tell the default of 25 is a deliberate keep, not an oversight.
- `C-HISTORY-PAGER`'s reserved `COMPONENTS.yaml` record moves from `planned` to `done`, with its responsibility and
  three consumers checked against what shipped and corrected if they drifted.
- `HistoryPager.test.tsx` pins the numbering and ellipsis at page 1, a middle page, and the last page; the edge
  disabling; the `aria-current` marker; and that selecting a size emits page 1. The three page suites keep every paging
  assertion, with `getByRole("button", {name: "Next page"})` preserved or replaced by a name the handoff states.
- `notification-history.spec.ts` keeps its `Page 1 of` assertion and gains one that jumps to the last page and back;
  `search-history.spec.ts` gains one that sets a page size, reloads, and finds it still applied.
- Screenshot strip per `../README.md` *Visual Gate*: the pager at page 1, at a middle page with the ellipsis, and on a
  single-page result, at 1280x800 and 390x844 (where the numbered run must not force sideways scroll).
